# 2026-07-02

## Benchmark reorganisation

Moved benchmarks from `test/performance/` → `bench/` at project root, decoupled from the test harness (no SimpleCov, no `test/test_helper.rb`). Created `bench/benchmark_helper.rb`. Stripped Money-gem references from core/memory/regression benchmarks. Isolated competitive benchmarks in `bench/money/` and `bench/shopify/` with per-directory Gemfiles. Updated `bin/bench_check`, `AGENTS.md`, `README.md`, and `doc/agents/copilot-instructions.md` paths.

## v1.9.7 release

Bumped version 1.9.6 → 1.9.7. Updated `CHANGELOG.md` documenting format disambiguation, compiled formatting lambdas, and the benchmark reorg.

## `Money#initialize` now calls `.to_r` on amount

Single guard at the boundary guarantees `@amount` is always `Rational`. Fixes two bugs:
- `eql?`/`hash` contract violation for zero-subunit currencies (e.g. JPY) where `@amount` was an `Integer`.
- `Integer#to_d` arity crash on BigDecimal ≥4.1.2 (`to_d` with no args returns `BigDecimal` with 0 precision; `.to_d(0)` matches old behaviour).

## `Currency.resolve` duck-typing

Extended `Currency.resolve` to accept objects responding to `#to_currency` (returns `Currency`) or `#currency_code` (returns `String`). `#to_currency` takes precedence. Wrong return types raise `ArgumentError`. Added 10 tests.

## Locale formatting — `locale:` kwarg

Added `locale:` kwarg to `format`/`to_fs`. The `Mint.locale_backend` callable now receives the locale (arity-aware — arity-0 lambdas work unchanged). Accepts symbols and strings. Added 6 tests. Updated README with ready-to-paste snippet (en, pt, de, fr, ja).

## ROADMAP.md update

Added `from_hash` / `from_json` (Medium priority) and `to_msgpack` / `from_msgpack` (Low, demand-driven) serialisation items.

## Investigated and rejected

- `to_d` caching: `amount.to_d(0)` is already the fastest path (~3M ops/sec). Cached `@subunits` is 1.07x faster but adds memory to every Money object — not worth it.
- Format engine regex simplification: `\z` fails when template text trails the integral part. The existing `(?:[^\d]|$)` anchor stays.
